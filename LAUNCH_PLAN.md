# CamouFlow AI workflow launch plan

The implementation is ready for controlled pilots, not proof of popularity. Launch around one repeatable extraction task and verify provider quality and onboarding before wider promotion.

## Positioning

**Describe once. Review the result. Replay a browser workflow without a model.**

First audience: people collecting structured data from small catalogs/reports across isolated browser profiles. Lead with one demonstrable job, not fingerprint settings, a marketplace or an unlimited autonomous-agent promise.

## Implemented foundation

- An isolated synthetic catalog, separate demo profile and explicit start.
- Structured table/text outputs, sources, preview and JSON/CSV export.
- Operator confirmations, questions, pause/stop and honest final statuses.
- Exact input parameterization, read-only replay/output schema checks, reviewed starters.
- Local history, workspace protection, shareable workflow exports.
- Local JSON CLI, optional restricted stdio MCP, inactive n8n example.
- English/Russian walkthrough and reproducible verification commands.

## Before publishing

1. Select one real Chat Completions provider/model and one local model. Manually run the demo three times each. Check quality, pricing and failures; fixture tests do not prove model quality.
2. Record a **real** 45–60 second clip: describe task → inspect table/source → export → parameterize URL → replay changed data without model requests. Show mistakes honestly; no fabricated UI/results.
3. Attach the fresh tested Windows build to a reviewed release. Current source changes are not a published version; don't promise integration support for an older release.
4. Run the n8n example in the intended deployment. It is currently only an example, not a certified connector.
5. Ask five target users to reach their first useful export without coaching. Record blockers with consent; revise labels/defaults before expanding features.

## Publication sequence (manual approval required)

1. GitHub release + README demo clip + three documented starters.
2. A concrete walkthrough for browser-automation communities: include platform, local/cloud data boundaries and limitations. Respect self-promotion rules.
3. One small case study: a real user saves time on a repeatable catalog/report job. Don't invent numbers.
4. A narrow contribution request: selectors/starter workflows for permitted sites, not a broad “star us” message. Review exported files for personal data first.

Replace the link only after release. Nothing in this plan authorizes posting, pushing or buying traffic.

## Measure before adding more

Use consent-based manual pilot notes first; no hidden telemetry was added.

- Activation: users who export useful data / users who start onboarding.
- Repeatability: successful reviewed second runs / users who save a workflow.
- Retention: users repeating the same useful workflow within seven days.
- Support friction: top three onboarding failures, time to first export, provider/model used.

Do not equate stars or fixture success with product-market fit. Prioritize fixing the largest observed onboarding failure. Multi-URL crawlers, broad connector catalogs and hosted execution come only after real repeated demand and explicit scope.
