# Участие в разработке CamouFlow

Принимаем сообщения об ошибках и предложения на русском и английском.
Соблюдайте [правила общения](CODE_OF_CONDUCT.md).

## Перед изменениями

- Проверьте существующие issues. Для большой задачи сначала опишите проблему и объём изменений.
- Воспроизводите ошибки на тестовых профилях. Прикладывайте минимальный пример и очищенные логи.
- Об уязвимостях сообщайте **приватно** по [SECURITY.md](SECURITY.md), не через публичный issue.
- Не публикуйте ключи, cookies, прокси-пароли, реальные профили и данные рабочих пространств.

## Локальный запуск

Из корня репозитория, Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install pytest ruff
.\.venv\Scripts\python.exe main.py
```

Движкам нужны отдельные загрузки и настройки; бинарники не коммитим.
Настройка приложения — в [README.ru.md](README.ru.md), сборка Glint — в
[native/BUILDING.md](native/BUILDING.md). Не дублируйте инструкции сборки в отчётах.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m compileall -q app main.py scripts
.\.venv\Scripts\python.exe -m ruff check app --select F821,F822,F823,E9
.\.venv\Scripts\python.exe -m pytest -q
```

При изменении упаковки или runtime дополнительно:

```powershell
.\.venv\Scripts\python.exe scripts/verify_release.py --build --runtime
```

Сначала установите и настройте необходимые движки. Исходные тесты, запуск
упакованного приложения и проверка собственного браузерного бинарника — разные доказательства.

## Изменения и pull request

- Целевая ветка — `main`. Изменение должно решать конкретную задачу без постороннего рефакторинга.
- Следуйте существующим Python/QML-паттернам, переиспользуйте компоненты и утилиты.
- Добавляйте регрессионные проверки в существующие тесты; обновляйте документацию.
- Текстовые файлы сохраняйте в UTF-8 без BOM. Сохраняйте схемы профилей, engine ID и API.
- Для интерфейса проверяйте клавиатуру, размеры окна и читаемость; прикладывайте скриншоты.
- Для патчей Glint указывайте upstream revision, ограничения, отрицательные контроли
  и результаты native/runtime-тестов. Не меняйте входные файлы активной сборки.

Glint пока является preview. Неприменённый или нескомпилированный патч — не
готовая функция. Windows-проверки не подтверждают Linux/macOS; результат одного
сайта не доказывает невидимость или гарантированное прохождение CAPTCHA.

Приватный `server/`, секреты, личные профили, загрузки, сборочные артефакты,
машинные отчёты и рабочие дневники остаются вне публичного Git.
